01 · Intake

Point it at a context.

Three context classes, one intake. Parallax reads what is already there. It does not ask you to model your operation first, because the model is the thing it is supposed to produce.

Class 01 — business data

A schema and its rows

Orders, ledgers, inventory, tickets, payroll. The conservation identity is usually already in there: money, stock, hours, seats. Finding it is the first act of declaring a domain.

Class 02 — agent workspace

An agent's own history

Tool calls, messages, model contexts. High-dimensional and partly unserialisable, so it is projected into typed observations rather than checked directly. Agent state is never the world state.

Class 03 — local filesystem

An arbitrary directory

Files, commits, exports, logs. No integration and no schema agreed in advance. Each class ships a seed template — a starting proposal you edit down rather than a blank page.

Nothing is inferred from a category name. The proposal is assembled from the rows and files that are actually present.

02 · Proposal

It proposes an ontology. You accept it.

A model's only job on the dynamics path is reading a mess into typed observations. What it proposes arrives as a diff over six declaration slots, each line carrying where it came from. Nothing is active until you accept it, and you can accept part of it.

You are approving a model of your own operation, not a model's opinion of it. An empty slot is the correct answer when the context does not support one; a plausible guess is not.

Slots are open. Add a field the proposal missed, replace the projection with your own model behind the plugin harness, bring a third-party forecaster in as a policy. The six operators do not change, and that is precisely what makes everything above them safe to change.

03 · Trajectory

Roll it forward under candidate decisions.

The log is append-only, so a fork is a branch record with a parent and a fork point. Creating a future costs nothing. Only evaluating one costs anything. Two branches that share a past can be compared, because a tick means the same thing on both.

04 · Typing

Every answer is typed observed or simulated.

A figure that came out of your history and a figure that came out of a projection are not the same kind of thing. A system that renders them identically is lying by layout. So the type travels with the value, everywhere, including into the API.

A branch is only as reproducible as its weakest input. The class is computed as the meet of the branch's own class and every input it consumed, so it can only ever fall — and an adapter is never allowed to certify its own class.

05 · Surface

The agent is a user, not a client library.

Every capability a human can reach, an agent reaches through the same surface, with the same authorisation, and with errors that are typed rather than narrated. There is no privileged human path and no second-class programmatic one.

06 · Objections

Reasonable things to distrust about this.

It is still a simulation. Why would I trust the number?

Because one arm of the comparison is not simulated. Every branch is scored against the recorded history it forked from, so a replay that cannot reproduce what already happened is visibly wrong long before anyone uses it to predict.

Is a language model computing my numbers?

No. A model proposes the ontology and reads messy input into typed observations. You accept the ontology. The transition function and the invariants are code, and nothing downstream of the projection is a model's opinion.

What if the proposed ontology is wrong for my business?

Then you edit it before it is active, and keep editing it afterwards. Types are open: add the field the proposal missed, or attach your own model behind the plugin harness. The six operators stay closed, which is what makes the rest safe to change.

We already A/B test.

A/B testing spends real customers and real weeks, and it cannot evaluate a decision you only make once. A fork costs a branch record. The two compose — use this to decide what is worth testing for real.

Our context is a mess.

Then the proposal comes back smaller. It is assembled from the rows and files that are actually present, and a slot with no support arrives empty rather than invented. An empty slot is information about your operation, not a failure of the tool.

07 · Start

Bring one context and one thing that must never be true.

An ontology is a record, not a codebase: what the state is, what actions exist, how an observation folds into the state, and what must always hold. Everything else is the same runtime, and the runtime never changes when a domain arrives.
